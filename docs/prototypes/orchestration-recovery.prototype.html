THROWAWAY LOGIC PROTOTYPE

两小时播客，断了以后从哪里继续？

这个原型让你亲手推动一次中文收听版的生产状态。它不调用阿里云，也不生成音频；它只验证编排规则是否符合你对“快、可恢复、不重复花钱”的理解。

要回答的问题：五个有序阶段、异步 ASR、分块并发翻译与配音、确定性缓存和清理规则，能否组成一个既能快速运行、又能在两小时任务中断后只重做未完成部分的模型？

建议锁定的规则

  • 阶段固定为：准备输入 → 英文识别 → 中文翻译 → 中文语音 → 合成 MP3。
  • ASR 只提交一次整文件异步任务；重启后用已保存的任务号继续查询，不重复提交。
  • 翻译与 TTS 都按块提交，起始并发为 4；TTS 另受 150 RPM 平滑限速。
  • TTS 每块不超过 500 字符，统一使用标准旁白音色 Andre。
  • 每个成功块先原子写入，再更新清单；完成块永不因进程重启而重做。
  • 模型、地域、音色或规范化文本改变时，缓存身份改变，不混用旧产物。
  • 只自动重试限流、超时和临时服务错误；认证、参数、配额错误必须停下来。
  • 用户接受 MP3 后只清理临时工作文件；报告、清单、计费记录、最终 MP3 保留。
